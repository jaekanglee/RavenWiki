Raven: API vs MCP — 어느 쪽이 write?

한 줄 답: API가 write. MCP는 API의 protocol adapter일 뿐. write 안 함.

4개 진입점 ❌. 3개 진입점 (CLI / API / Dashboard) + 1개 protocol adapter (MCP). 사람은 Dashboard나 CLI로 일하고, 에이전트는 MCP client (Cursor/Claude/Hermes)로 일함. 하지만 진짜 write는 모두 API로 흐름. MCP는 단지 protocol 변환 (JSON-RPC over stdio/HTTP) 일 뿐.

2. 코드 차이

2.1 API — write 경로 (진짜)

# raven/api/server.py (FastAPI)
@app.post("/api/vaults/{vault_name}/pages")
async def create_page(vault_name: str, payload: PageCreate):
    vault = registry.get(vault_name)
    contracts.write_page(  # ← 진짜 write
        vault, payload.slug, payload.content,
        title=payload.title, type=payload.type, tags=payload.tags,
        actor=payload.actor, ...
    )
    return {"ok": True, "slug": ...}

2.2 MCP — protocol adapter (write 위임)

# raven/mcp/tools/write.py
def mcp_create_page(slug: str, content: str, ...):
    # MCP는 단순히 API endpoint를 호출
    response = requests.post(
        f"http://127.0.0.1:8765/api/vaults/{vault_name}/pages",
        json={"slug": slug, "content": content, ...}
    )
    return response.json()

→ MCP의 write_page 함수는 내부적으로 API endpoint를 호출. write 로직 자체는 API에만 존재.

3. Write 경로 비교표

인터페이스 사용자 Write 경로 구현체
Dashboard 사람 Dashboard → API → core.write React 19 + Vite (read-write UI)
CLI 사람/스크립트 CLI → API 또는 직접 core.write Typer 9 commands
MCP 에이전트 MCP → API → core.write (위임) FastMCP (protocol adapter only)

4. 결론

  • API가 단일 write 경로 — Dashboard/CLI/MCP 모두 API를 통해 write.
  • MCP = API의 MCP-protocol 변환기 — JSON-RPC over stdio/HTTP 받아서 API로 위임.
  • 사람용 vs 에이전트용 인터페이스가 다른 이유 — 사람(브라우저/터미널)과 에이전트(MCP client) 도구 자체가 다름. write 경로는 동일.
  • 4개 진입점 표현이 부정확 — 정직한 표현: 3개 진입점 + 1개 protocol adapter.
